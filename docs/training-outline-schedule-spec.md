# Specification: โครงร่างและกำหนดการอบรม

## เป้าหมาย

รวมฟังก์ชั่น **โครงร่างอบรม** และ **กำหนดการอบรม** เดิมไว้ใน Node เดียวชื่อ **โครงร่างและกำหนดการอบรม** แล้วใช้ Node นี้แทนที่ฟังก์ชั่น **ยป.1** ทั้งหมดสำหรับงานใหม่

ผู้ใช้ต้องกรอกข้อมูลใน workflow เดียว กดบันทึก/สร้างเอกสารครั้งเดียว และได้เอกสารไฟล์เดียวที่เรียงหน้าแบบนี้:

1. หน้าแรก: โครงร่างอบรม
2. หน้าถัดไป: กำหนดการอบรม วันละ 1 หน้า

งานเก่าที่เคยสร้างจากโครงร่างอบรมหรือกำหนดการอบรมแยกกันให้คงไว้ตามเดิม ไม่ต้อง migrate ย้อนหลัง

## ขอบเขต

### ต้องทำ

- แทนที่ Node **ยป.1** ด้วย Node ใหม่ชื่อ **โครงร่างและกำหนดการอบรม**
- ย้ายฟอร์ม/logic ของ **โครงร่างอบรมเดิม** และ **กำหนดการอบรมเดิม** มาอยู่ใน Node ใหม่นี้
- ใช้รูปแบบฟอร์มเดิมเป็นฐาน ไม่ออกแบบ field ใหม่โดยไม่จำเป็น
- ใช้ step ในหน้าเดียว:
  1. Step 1: โครงร่างอบรม
  2. Step 2: กำหนดการอบรม
  3. Step 3: ตรวจสอบ/สร้างเอกสาร ถ้าระบบเดิมมีขั้นตอน preview/confirmation
- ต้องกรอก required field ของ Step 1 ให้ครบก่อนจึงเข้า Step 2 ได้
- ตัวเลือกวันอบรมอยู่ใน Step 1
- วันที่อบรมเป็น source of truth จาก Step 1 เท่านั้น Step 2 แก้วันที่ไม่ได้
- Step 2 สร้างตารางกำหนดการตามวันที่จาก Step 1
- แต่ละวันมีตารางเวลาของตัวเอง ตามกำหนดการของวิทยากร
- สร้างเอกสารครั้งเดียวเป็นไฟล์เดียว โดยต่อ template เดิมของโครงร่างอบรมและกำหนดการอบรมเข้าด้วยกัน

### ไม่ทำในรอบนี้

- ไม่ migrate เอกสาร/ข้อมูลเก่าเข้าฟอร์มใหม่
- ไม่ให้กำหนดการแยกเดิมหรือโครงร่างแยกเดิมเป็น workflow สร้างงานใหม่อีกต่อไป
- ไม่ให้ Step 2 แก้วันที่แล้ว sync กลับ Step 1
- ไม่เพิ่มข้อมูลวิทยากรแบบเต็มจากกำหนดการ เพราะประวัติวิทยากรส่วนใหญ่ต้องค้นเองภายหลัง

## Flow ผู้ใช้

1. ผู้ใช้เปิด Node **โครงร่างและกำหนดการอบรม**
2. ระบบแสดง Step 1: โครงร่างอบรม โดยใช้ field/layout จากฟอร์มโครงร่างอบรมเดิม
3. ผู้ใช้เลือกประเภทวันอบรมใน Step 1:
   - จัดอบรมวันเดียว
   - จัดอบรมหลายวันติดกัน
   - จัดอบรมหลายวันแยกกัน
4. ระบบ validate required field ของ Step 1
5. ถ้าครบ ผู้ใช้ไป Step 2 ได้
6. ระบบสร้างรายการวันอบรมจริงจาก Step 1 แล้วแสดงเป็นตารางกำหนดการรายวัน
7. ผู้ใช้กรอกกำหนดการของแต่ละวัน โดยแต่ละวันมี session/time table ของตัวเอง
8. ผู้ใช้เลือกวิทยากรจากข้อมูลหลัก หรือพิมพ์ชื่อใหม่ใน session ได้
9. ถ้าพิมพ์วิทยากรใหม่ ระบบมี checkbox **เพิ่มเข้าข้อมูลหลัก** และบันทึกเฉพาะชื่อวิทยากร
10. ผู้ใช้กดบันทึก/สร้างเอกสารครั้งเดียว
11. ระบบสร้างเอกสารไฟล์เดียว: หน้าแรกโครงร่างอบรม หน้า 2 เป็นต้นไปเป็นกำหนดการ วันละ 1 หน้า

## โครงสร้างข้อมูลที่ต้องการ

ใช้โครงสร้างที่ AI และระบบอ่านง่าย โดย normalize วันที่ทุกแบบให้กลายเป็นรายการวันอบรมจริงเสมอ

```json
{
  "nodeType": "training_outline_schedule",
  "title": "โครงร่างและกำหนดการอบรม",
  "outline": {
    "fields": "ใช้ field เดิมของโครงร่างอบรม"
  },
  "trainingDateMode": "single_day | continuous_days | separate_days",
  "trainingDateInput": {
    "singleDate": "YYYY-MM-DD",
    "startDate": "YYYY-MM-DD",
    "endDate": "YYYY-MM-DD",
    "separateDates": ["YYYY-MM-DD"]
  },
  "trainingDays": [
    {
      "date": "YYYY-MM-DD",
      "sessions": [
        {
          "startTime": "HH:mm",
          "endTime": "HH:mm",
          "topic": "",
          "content": "",
          "speaker": {
            "id": "optional-master-speaker-id",
            "name": "",
            "isNew": false,
            "addToMaster": false
          },
          "note": ""
        }
      ]
    }
  ]
}
```

`trainingDays` เป็น source หลักสำหรับสร้างหน้ากำหนดการ ไม่ควรให้ code generation หรือ AI agent ไปเดาจากข้อความวันที่เองหลังจาก normalize แล้ว

## กติกาวันอบรม

### จัดอบรมวันเดียว

- ผู้ใช้เลือกวันที่เดียว
- ระบบสร้าง `trainingDays` 1 รายการ
- เอกสารกำหนดการมี 1 หน้า

### จัดอบรมหลายวันติดกัน

- ผู้ใช้เลือกวันที่เริ่มต้นและวันที่สิ้นสุด
- ระบบสร้างวันที่ต่อเนื่องทุกวันระหว่าง start-end
- ไม่เดาเรื่องวันหยุด เสาร์ อาทิตย์ หรือวันหยุดราชการ เพราะผู้ใช้เลือก mode นี้เพื่อบอกว่าจัดต่อเนื่องจริง
- เอกสารกำหนดการมีวันละ 1 หน้า

### จัดอบรมหลายวันแยกกัน

- ผู้ใช้เพิ่มวันที่อบรมเป็นรายการ
- ระบบ sort วันตามลำดับวันที่จริง
- ระบบสร้าง `trainingDays` ตามวันที่ที่เลือก
- เอกสารกำหนดการมีวันละ 1 หน้า

## กติกาการดึงข้อมูลระหว่าง Step

ลำดับคือ **โครงร่างก่อน แล้วค่อยกำหนดการ**

- Step 1 เป็นแหล่งข้อมูลตั้งต้นของงาน
- Step 2 ดึงเฉพาะข้อมูลที่ฟอร์มกำหนดการเดิมต้องใช้จริงจาก Step 1
- ไม่ดึงกลุ่มเป้าหมายไปกำหนดการ
- หัวข้อหลักและเนื้อหาเป็นข้อมูลของกำหนดการ ไม่ใช่ข้อมูลกลางจากโครงร่าง
- วิทยากรใช้ในกำหนดการและใช้เป็นหัวตาราง/ข้อมูลในตารางตามฟอร์มเดิมได้

## กติกาวิทยากร

- ในแต่ละ session ผู้ใช้เลือกวิทยากรจากข้อมูลหลักได้
- ผู้ใช้พิมพ์วิทยากรใหม่ได้
- ถ้าพิมพ์วิทยากรใหม่ ให้มี checkbox **เพิ่มเข้าข้อมูลหลัก**
- ถ้าเลือกเพิ่มเข้าข้อมูลหลัก ให้บันทึกเฉพาะชื่อวิทยากร รายละเอียดประวัติ/ตำแหน่ง/หน่วยงานค่อยเติมภายหลัง
- ต้องป้องกันการเพิ่มชื่อว่างหรือชื่อซ้ำแบบตรงตัว

## เอกสารผลลัพธ์

- กดสร้างเอกสารครั้งเดียว
- Output เป็นไฟล์เดียว
- หน้าแรกใช้ template/หน้าตาเดิมของ **โครงร่างอบรม**
- หน้าถัดไปใช้ template/หน้าตาเดิมของ **กำหนดการอบรม**
- ถ้ามีหลายวัน ให้กำหนดการแยกวันละ 1 หน้า
- ลำดับหน้าในเอกสารต้องเป็น:
  1. โครงร่างอบรม
  2. กำหนดการวันที่ 1
  3. กำหนดการวันที่ 2
  4. ต่อไปตาม `trainingDays`

## Acceptance Criteria

- ผู้ใช้ไม่เห็น Node **ยป.1** เป็น workflow สร้างงานใหม่อีกต่อไป และเห็น Node **โครงร่างและกำหนดการอบรม** แทน
- Step 1 ใช้ field/layout จากโครงร่างอบรมเดิม และมีตัวเลือกประเภทวันอบรม
- ถ้า required field ของ Step 1 ไม่ครบ ระบบไม่ให้ไป Step 2
- Step 2 สร้างรายการวันจาก Step 1 ถูกต้องทุก mode
- Step 2 แก้วันที่ไม่ได้ ถ้าจะเปลี่ยนวันที่ต้องกลับไป Step 1
- แต่ละวันใน Step 2 มีตาราง session แยกกัน
- วิทยากรเลือกจากข้อมูลหลักหรือพิมพ์ใหม่ได้
- วิทยากรใหม่มี checkbox เพิ่มเข้าข้อมูลหลัก และบันทึกเฉพาะชื่อเมื่อเลือก checkbox
- ปุ่มบันทึก/สร้างเอกสารมีครั้งเดียวสำหรับทั้ง Node
- เอกสารที่สร้างเป็นไฟล์เดียว หน้าแรกเป็นโครงร่าง หน้าถัดไปเป็นกำหนดการวันละ 1 หน้า
- งานเก่าเปิดดูได้ตามเดิมและไม่ถูก migrate โดยอัตโนมัติ

## แผนทดสอบ

- ทดสอบ single day: ได้ `trainingDays` 1 วัน และเอกสารมีหน้าโครงร่าง + กำหนดการ 1 หน้า
- ทดสอบ continuous days: start-end 3 วัน ได้กำหนดการ 3 หน้า
- ทดสอบ separate days: เลือกวันที่ไม่ติดกัน 3 วัน ได้กำหนดการ 3 หน้าเรียงวันที่
- ทดสอบ validate Step 1: ขาด required field แล้วไป Step 2 ไม่ได้
- ทดสอบกลับไปแก้วันที่ใน Step 1 แล้ว Step 2 regenerate/เตือนผลกระทบกับตารางเดิมตาม behavior ที่ implement เลือก
- ทดสอบแต่ละวันมี session ไม่เหมือนกันได้
- ทดสอบเลือกวิทยากรจาก master data
- ทดสอบพิมพ์วิทยากรใหม่โดยไม่ติ๊กเพิ่มเข้าข้อมูลหลัก
- ทดสอบพิมพ์วิทยากรใหม่และติ๊กเพิ่มเข้าข้อมูลหลัก แล้ว master data เพิ่มเฉพาะชื่อ
- ทดสอบสร้างเอกสารและตรวจลำดับหน้า/template
